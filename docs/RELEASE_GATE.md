# Vehicle Book Release Gate

This is a local, simulated knowledge-release gate. It is not real OEM content approval or production safety certification.

## Purpose

The gate combines Registry/source validation, deterministic retrieval evaluation, offline Answer Replay, pytest, and a versioned baseline comparison into one release decision. It never calls an LLM or reads API credentials unless `--answer-mode live` is explicitly requested.

## Decisions and checks

The only overall decisions are `PASS`, `FAIL`, and `BLOCKED`.

- `PASS`: every Hard Gate passes.
- `FAIL`: one or more Hard Gates fail.
- `BLOCKED`: a required candidate input, baseline, manifest, or required comparison is unavailable.

`REVIEW`, `NOT_RUN`, and `NOT_COMPARABLE` are per-check statuses only. They never replace the overall decision.

Hard Gates require schema/metadata validity, zero duplicate active IDs and broken citation anchors, zero wrong-vehicle/version retrieval, Recall@3 of at least 90% overall and 80% for every positive required slice, citation correctness of at least 95%, expected-fallback-only accuracy of at least 90%, zero critical errors, a passing pytest run, and no baseline regression.

Required slices are OEM, model, software-version family, `high_or_critical`, and `no-answer`. No-answer slices report no-answer/fallback behavior rather than Recall@3 because they have no positive gold chunk.

Soft Gates report local retrieval P95 latency (`REVIEW` above 500 ms) and Live API acceptance. Live is `NOT_RUN` unless explicitly requested; missing configuration or an unsuccessful run can never produce `PASS`.

## Inputs and baseline contract

Candidate reports are generated by the existing scripts and contain:

- `retrieval_summary.json`
- `retrieval_case_results.json`
- `answer_summary.json`
- `answer_case_results.json`

The committed baseline lives at `data/baselines/vehicle_book_release_v1/`. It contains those reports plus `baseline_manifest.json`. The manifest records baseline ID, UTC creation time, Git revision, dataset paths/checksums, registry/document-source checksum, both `top_k` values, report format version, and baseline Hard Metric values.

The gate compares checksums, paths, report format, and `top_k` before comparing metrics. A mismatch is `NOT_COMPARABLE` and blocks the release conclusion because baseline comparison is required.

## Run

```powershell
python scripts\run_release_gate.py
```

This runs pytest, retrieval evaluation, Answer Replay, local latency measurement, and the gate. It writes `outputs/release_gate/release_gate_summary.json` and `outputs/release_gate/release_gate_report.md`.

Optional Live acceptance must be explicit:

```powershell
python scripts\run_release_gate.py --answer-mode live
```

To create a new baseline intentionally, use an empty target directory:

```powershell
python scripts\run_release_gate.py --initialize-baseline --baseline-dir data\baselines\vehicle_book_release_v1
```

An existing baseline is never overwritten unless `--force` is provided explicitly. Ordinary evaluation commands only write `outputs/` and never overwrite the versioned baseline.

The gate does not publish content, update a Registry, change document status, call a cloud service by default, or replace human/OEM approval.
